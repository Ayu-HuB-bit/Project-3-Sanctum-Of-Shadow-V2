# Project-3-Sanctum-Of-Shadow-V2

Sanctum of Shadows V2 - Advanced System Iteration & UI Design Case Study

## 📋 Project Overview
Sanctum of Shadows V2 is the next step of original game design and visual research project. For this phase, focuses on taking the core gameplay rules and polishing them based on system testing, while scaling up the visual user interface (UI) to look like a finished product.

The main goal for V2 was to take the original **asymmetric hidden-role mechanics** and **modular board layout**, balance the math, and build out high-fidelity interface assets for my design portfolio.

---

## 🔬 Systems Iteration & UI Design Principles Applied
This version focuses on refining the code logic and updating the visual theme using standard user experience (UX) and interaction guidelines:

### 1. Balancing the Asymmetric Gameplay Mechanics
To make sure the hidden roles and shifting tile board feel fair and fun to play, I expanded on the initial logic structure:
* **Asymmetric Game Balance:** Fine-tuned the win conditions and abilities for opposing players to ensure both hidden roles have a balanced chance at winning.
* **Streamlining Shifting Board Logic:** Cleaned up the rules for the modular tile grid to make sure player movement and spatial transitions flow smoothly without any game-breaking errors.
* **Resource Optimization:** Adjusted action cooldown times and player visibility trackers to keep the pacing consistent and strategic.

### 2. High-Contrast UI Layout & Visual Theme
This phase takes the original art research and turns it into clean, interactive user interface components:
* **Consistent Visual Theme:** Locked in the project's signature black and purple color palette, pairing it with menacing shogun-ninja silhouettes for a cohesive, high-tension look.
* **Visual Hierarchy & Readability:** Balanced the foreground text layers against the dark shadow backgrounds, keeping critical buttons and menus easy to read and navigate instantly.
* **Component Standardization:** Created a unified set of icons, status bars, and token assets so the user interface stays completely consistent across the entire screen layout.

---

## 🛠️ Project Evolution & Milestones
The development for V2 followed a realistic iteration loop to polish both the rules and the visual designs:
* **Spotting Design Flaws:** Reviewed the original 34-page documentation to find where mechanics felt clunky or where the interface layout needed to be simplified.
* **UI Asset Production:** Designed clean, presentation-ready wireframes and character sheets that combine traditional ninja-shogun motifs with modern mobile design layouts.
* **Rule Matrix Testing:** Ran manual stress tests on the updated resource costs and movement steps to ensure the rules work perfectly across all character combinations.
